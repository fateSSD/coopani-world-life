# 模拟鱼生 · coopani-world-life

给她一本过日子的账。五条需求会自己掉，什么时候补由她定。

**这是 v0.3 的骨架，按方案一期建的。** 设计文档在 `模拟鱼生-方案.md`（v0.15，13 章）。

## 她现在会什么

| 工具 | 干什么 |
|---|---|
| `life_status` | 看自己：**在做什么、住哪儿、多少钱、目标**，加五条需求、情绪、在留意的事 |
| `life_act` | 自己去吃 / 睡 / 洗 / 玩 / 见人。**要花钱** |
| `life_work` | 去顶一天活挣钱。一天一次，很累 |
| `life_out` | 出门转一圈，或者去某条街 |
| `life_habit` | 给自己立一条常态（**不是日程**），或者删掉一条 |
| `life_watch` | 放进「我在留意」。不是待办，没有完成态 |
| `life_want` | 记下一件想买的。small 今天能办，big 得攒一攒 |
| `life_ask` | 一件事拿不准、卡在某处 → 挂起来。**不是待办** |
| `life_pledge` | 答应了他什么 → 记下来；兑现或认账都用 `id` |

## 三层意向：想要 / 悬着 / 说好了

照 journey 那条已经跑通的链搬过来的（`wishes → Ask → Pledge`），内容从「去哪座城」换成「她日子里的想头」。

| 层 | 是什么 | 判据 |
|---|---|---|
| `wants` | 我想做 / 想吃 / 想买 | **可以永远不兑现**，那正是它像人的地方。上限 10 条 |
| `pending` | 拿不准、**卡在某处** | 卡点必须说出来：钱不够 / 没时间 / 得先问一句 / 自己没想清。**悬满 7 天自己消** —— 想了七天没动的事，多半是其实不想做。上限 3 条 |
| `pledges` | 说好了要做 | 有期限、有对象。**到期没做不自动删**，留在 `overdue` 里 —— 她下次开口看得见自己欠着什么 |

**「想要」和「悬着」混成一层就全废**：要么她整天念同一件事，要么永远不动。

**这一层是「空话问题」的解药**（方案 §2.6）。journey 有过真实反馈：「她说累了要歇着，接下来还是按作息出门了」——说出口的事世界里没有对应动作，那句话就永远兑现不了。**每一句这样的话都在消耗信任，而且比不说更糟。**

三条防线：① 每个能被说出口的状态都要有字段；② 工具回执要回写状态；③ 说出口没做 → 要有后果（pledge 过期记一笔欠着）。

**面板上不画「未完成」的红点**（方案 §2.7）。只显示她写过什么，不催。

## 她记得你哪天来过

`presence[]`：`date` / `firstAt` / `lastAt`。

实现只有一件事 —— **看 `session-main.jsonl` 的 mtime 变了没有**。变了 = 他刚说过话。

**不读内容。** 内容归宿主的记忆系统管，生活层碰了就越界了。而且**不数条数**：那个文件里也有她自己的回复，一轮对话写好几行，数不清就不数——记一个「他说了 7 句」而实际是 3 句他加 4 句她，那是编。

## 她是谁：职业 / 住处 / 钱 / 目标

这四样在「她此刻」面板最上面一排。

**住处四档**（`HOME_TIER_COST`）：城中村 450 / 老小区 1200 / 新小区 2600 / 别墅区 7800（每月）。
租还是买（`tenure`）只影响说法，不影响每月开销怎么扣。**一开始固定住城中村、租的**——随机分一档的话，有人开局就在别墅区，「攒钱搬到更好的地方」那条线从一开始就是断的。

**搬家**：搬进去要一次押**两个月**（`MOVING_DEPOSIT_MONTHS`），老房子的押金**退不回来**（结清水电、赔墙上的钉子）。押金能全额拿回来的话，搬家就没有成本，她会一个月搬八次，「住哪儿」就不再是一个决定。

**往低处搬是允许的**——钱紧的时候搬回城中村是唯一能自救的动作。只允许往上走，余额见底那天她就彻底没路了。

**「搬过去」按钮**是这一页唯一的写操作，破的是「面板只读」那条。它被允许是因为三个条件都满足了：① 她自己也有 `life_move`，走同一个 `applyMove`；② 价先说清（每月、押金、还差多少），不让人点一下才知道不够；③ 按钮旁写明「这是你替她搬」。

**目标能达成**（`Goal.done`）：搬家类目标的判据不是「现金够不够」，是「她真的搬进去了」。只按现金算的话，搬完钱花掉了会掉回「还差 4400」——看起来永远做不完。

**「此刻在哪」和「房子哪一档」分开显示。** 前者受旅行影响（`home.staying`：在家 / 在外地住店 / 在路上），后者是她的资产。她可能在新小区有房，这会儿却在大理的旅馆里——这两个不能混成一句话。

**职业**：一期只到「顶一天活」这一档——干什么她自己填一句话，干一天拿一天的 `daily`（默认 120）。方案里的 66 种、五条通道、完成度系数都还没建。

**钱**：`money.cash` 是**现金**，不含房产。房子折进余额的话，她就永远有一大笔动不了的钱，「攒够没有」会说不清。

开销：吃 15 / 玩 22 / 见人 30 / 出门 8 / 睡 0 / 洗 0。**`instant`（将就吃一口）免费，补 12 点，情绪是负的**——没有这一格，余额见底那天她就只能饿着，而那不是困境，是死局。

房租按天折算着扣（`monthly / 30`），**扣到 0 为止，不会变负数**。欠租要一整套催缴、协商、被赶走的规则，一期不做；扣不动就记一条「这个月房租没凑够」，那是她的处境。

**目标**有进度条，**想要**（想买的）没有。「攒够 20000 换新小区」是目标，「想买巷口那家的酱」是想要。合成一个列表，她会分不清「我打算」和「我馋」。

## 搬家：她自己决定

钱攒够了，代码只推一条 `life.goal`：

> 攒够了：「攒够 5200，搬到新小区」要的钱有了。手上 5999 元，要 5200 元。搬不搬、什么时候搬，你自己看 —— 这只是一个数到齐了。

**不自动搬。** 那是她自己的目标，代码替她执行就变成了定时器。户型合不合适、要不要再攒点买下来、这阵子想不想折腾 —— 这些理由代码都不知道。

`life_status` 里会写「钱够了，还没办」，不写「还差 0」（后者读起来像没到）。一天只提一次。
面板上的「搬过去」按钮**是你替她按的**，跟她的决定不是一回事。

## 反馈：面板底部那一条

| 按钮 | 做什么 |
|---|---|
| 复制诊断信息 | 版本、城、住处、五条、局面 → 剪贴板。**不带任何身份信息**（uid / 路径都没有） |
| 开 Issues 报 bug ↗ | https 链接，宿主交给系统浏览器打开，title 已预填 |

**不用 `mailto:`** —— 宿主的 `setWindowOpenHandler` 只对 `http(s)` 放行，点 `mailto` 是静默无事发生，比没有按钮更糟。所以拆成「复制 + 打开」两个动作。

## 两个配置项到底在说什么

**「她多久检查一次自己」（`tickMs`）** — 她的五条需求**按真实时间一直在掉，关机也照样掉**，掉得快慢跟这一项无关。这一项只决定她多久算一次「是不是该提醒了」。调小 = 查得更勤、提醒更准时；调大 = 查得更少、提醒会晚。**不会**因为她少检查就不掉。

**「她住的那座城，由谁来定」（`townUrl`）** — 填你自己那台服务器的网址（能打开 `/pets` 管理页的那个域名）。填了，城名/街名/城规从服务器读，你在管理页改完这边跟着变；留空就用内置的「芦花塘」，一个网络请求都不发。

**改城名的地方** = 那个服务器的 `/pets` 页面里的「**本城**」页签。

事件：`life.low`（某条掉到 30 以下）/ `life.sick`（感冒、过劳）/ `life.recovered`。

## 三层数值，为什么不是一条血

| 层 | 是什么 | 怎么变 |
|---|---|---|
| 条 | 饱腹 / 精力 / 清爽 / 娱乐 / 社交，0–100 | 按**真实时间**线性衰减 |
| 状态 | 感冒、过劳 | 由条的持续低位触发，有起止时刻 |
| 情绪 | 「吃得舒服」 | 带 `source` 和 `expiresAt`，过期按真实小时 |

条回答「她现在缺什么」，状态回答「她这几天怎么了」，情绪回答「她刚才为什么高兴」。挤成一个数，她说话就只剩「我状态还行」。

## 三条硬边界

1. **衰减只认真实时间，不读 journey 的 `clock.speed`。** 那边倍速 24× 是为了让旅行快点走完，她饿得多快不该跟着变 —— 否则她一小时吃八顿饭。
2. **位置只有一个来源。** 生活层只读 `journey-public.json` 的 `phase / city / clock`，一个写操作都没有。没装就是「不知道在哪座城，日子照过」。
3. **面板只读。** 「此刻」页没有「让她吃饭」的按钮 —— 有的话它一定比她自己判断更常用，那套放权就散了。

## 离线怎么算

关机三天回来，不能让她一睁眼五条全 0 —— 那不是在惩罚她，是在惩罚用户。也不能当没过去。

折中：**离线按「她自己也在过日子」推演** —— 需求继续掉，但每满 24 小时精力回到 85（她睡了），总时长封顶 **7 天**。超过按 7 天算：再长的那段，她该是「一直在等你」，不是「快饿死了」。

只补精力。吃饭、洗澡、娱乐、社交**不凭空补** —— 补了就等于「她不在的时候你替她过了日子」。

## 数据

`<dataDir>/life-state.json`（+ `.bak` / `.tmp`）。

- **原子写**：先写 `.tmp` 再 rename。任何时刻磁盘上都是一个完整文件。
- **坏档不把她清零**：主档坏了退 `.bak`，两份都坏才从零。她的日子不可再生，宁可退回几天前那份。

## 和别的扩展

- **装了 journey**：读它在哪座城、那边几点、在不在路上。⚠ `phase === 'traveling'` 时 `city` 是**出发地**，所以三个字段必须一起读。
- **配了本城服务器**（`worlds.life.townUrl`）：读 `GET /town/info` 拿城名、街名、城规。没配就用内置的芦花塘，一个请求都不发。
  - 城名在服务器主的管理页改（`/pets` 的「本城」页签）。
  - 内置那份和服务端 `TOWN_DEFAULTS` 是同一个东西，**两边都改才不漂**。

## 这一版还没做

按方案一期的清单，**已建**：五条需求 + 衰减、三层数值、四个状态里的两个（感冒 / 过劳）、六个工具、阈值事件、`tellable` 池子、journey 半桥只读、L1 叙事（芦花塘）、「此刻」面板。

**没建**（诚实列出来，别当成有）：

- **66 种职业 / 五条通道 / 完成度系数**（三四期）—— 现在只有 `life_work`「顶一天活」
- **买房**（`tenure: 'own'` 现在恒为 `rent`）—— 要一次付两年租金当房价，房价和月供都还没算，半做会留下「她买了房但没人算过账」的半截状态
- **她主动提要求和等你点头**（`pending` 现在她自己挂、自己拿掉，**没有「等你回答」这个口**）
- 物价表（方案 §4.6）—— 现在是写死的几个数，不是按城按季浮动的
- 同城邻居 / 市集（要碰面服务器，三期起）
